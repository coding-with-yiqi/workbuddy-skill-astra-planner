## 宿主接口契约（harness 只能依赖这些，禁止假设别的东西存在）

$ASTRA_OUT/codex.log      codex 原始输出

入口：
- 编译：`ask_gpt.sh <task.md> [out_dir]`
- 跑自检：`ask_gpt.sh --check <out_dir>` —— 会**先按当前 PLAN.md 重新提取一次再跑**（幂等，可重复运行）

harness 硬约束：
- 不联网、不调用真实 codex、不依赖上面没列出的任何参数或环境变量
- 被测对象路径用 `$ASTRA_SUBJECT`；产物路径用 `$ASTRA_OUT`，或相对路径 `PLAN.md`（cwd 就是输出目录）
- 需要假 codex 时，用 shell 函数或临时脚本自建（放进 `PATH` 里即可，宿主是按 PATH 查找 codex 的）。宿主通过 **stdin** 把 prompt 喂给 codex，所以假 codex 里可以 `cat >/dev/null` 收下它
- 临时目录用 `mktemp -d`（走系统临时目录），**不要把临时目录建在 `$ASTRA_OUT` 里** —— 宿主对输出目录里的批量删除有安全拦截

- **断言行为，不断言源码**：不要 grep 脚本里有没有某个字面量（实现会重构），要断言实际效果（跑命令看退出码、看输出、看文件是否生成）

## 自检 Harness

一个或多个 bash 代码块。**每个代码块第一行必须是 `# harness/<名字>.sh`**（用于自动提取落盘），第二行 `#!/usr/bin/env bash`，第三行 `set -uo pipefail`。

硬要求：
- 每个脚本 ≤ 60 行，只做断言不做编排
- 幂等：可重复运行，不联网，不修改被测对象之外的东西
- 每个检查输出一行 `[PASS] <检查名>` 或 `[FAIL] <检查名> — 实际值 vs 期望值`
- 结尾汇总 `SUMMARY pass=N fail=M`，有 FAIL 时 `exit 1`，全绿时 `exit 0`
- 只断言，不修复
